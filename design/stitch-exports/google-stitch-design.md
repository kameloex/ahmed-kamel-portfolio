# Project: Ahmed Kamel — Original Interactive 3D Developer Portfolio

Act as a senior product designer, creative director, and interactive web experience designer.

Design an original, premium personal portfolio website for Ahmed Kamel, a software developer based in Alexandria, Egypt. The goal is to showcase his real software projects, demonstrate his technical range, and help recruiters, engineering teams, and freelance clients understand his capabilities.

This is NOT a request to clone an existing portfolio template. Create a distinctive visual identity and an experience with its own design logic.

## 1. Creative Direction

Explore the concept of an interactive digital environment where software projects feel like engineered artifacts inside a carefully designed spatial world.

The experience should communicate:
- Technical depth
- Creativity and independent thinking
- Precision and attention to detail
- Modern software engineering
- A strong personal identity

Use original spatial compositions, layered depth, perspective, floating architectural forms, subtle dimensional grids, and sophisticated transitions between sections.

The 3D elements must feel intentional and connected to the project content. Avoid generic floating cubes, excessive neon effects, gaming interfaces, generic AI-generated dashboards, and overused portfolio layouts.

The result should feel like a premium digital experience, not a collection of template sections.

## 2. Visual Identity

Primary direction: dark, minimal, editorial, futuristic, and sophisticated.

Suggested palette:
- Obsidian background: #080B10
- Near-white typography: #F5F7FA
- Ice blue accent: #77CFFF
- Secondary blue-gray: #9AAEBC
- Muted surfaces: #111923

Use ice blue selectively for depth cues, active elements, fine borders, selected text, and interactive states.

Typography should combine a distinctive display typeface with a highly readable sans-serif for body text. Consider Space Grotesk or a similar display typeface, paired with Inter or a similarly readable font.

Maintain excellent contrast, restrained glow, deliberate whitespace, consistent spacing, and a clear visual hierarchy.

## 3. Hero Experience

Design a memorable full-screen desktop hero.

Include:
- The name AHMED KAMEL
- A professional title such as "Software Developer — Web & Interactive Systems"
- A concise introduction focused on building practical digital products
- Primary action: Explore Selected Work
- Secondary action: Contact Me
- A clear navigation system
- A distinctive 3D visual centerpiece

The central visual should be an original dimensional composition that hints at interconnected software systems. Explore translucent layers, engineered structures, subtle orbital paths, and small project-related visual markers.

The 3D composition should support the message rather than obstruct it. Keep the name, value proposition, and primary action readable at all times.

Do not include a graduation year. Do not describe Ahmed as a graduate. Do not invent employment history, clients, awards, or performance metrics.

## 4. Portfolio Sections

Design a cohesive scrolling experience containing:

A. Hero

An immersive first impression with a clear message and an original spatial visual.

B. Selected Projects

Three visually distinctive project showcases. Each card should use the actual supplied project cover image, project name, concise description, and appropriate technology labels.

Do not make all three cards identical. The presentation may vary subtly to match each project's character, while preserving one consistent design system.

C. About

A concise professional introduction, emphasizing software development, problem solving, practical project work, and the ability to work across different technical domains.

D. Skills & Technologies

Group technologies by meaningful categories, such as web development, programming, databases, and tools. Do not create an oversized wall of technology logos.

E. Experience & Journey

A clean, credible presentation of relevant training, freelance work, and technical or educational experience. Use only supplied information.

F. Contact

A clear closing section with email, GitHub, LinkedIn, and a strong contact call to action. Use supplied contact details only.

## 6. Project Detail Experience

Design a reusable project case-study layout that can display:
- Project cover and title
- Project overview
- Problem and purpose
- Key features
- Technical implementation
- Technology stack
- Actual screenshots in a clean gallery
- Relevant technical challenges and learning outcomes
- Live demo and repository actions where real links exist

Use the real descriptions provided above. Do not invent project outcomes or claims.

## 7. Interaction and Motion Direction

Design interactions that can later be implemented with React, Three.js / React Three Fiber, and Motion.

Explore:
- Subtle mouse-responsive depth
- Gentle parallax
- Scroll-triggered reveals
- Smooth section transitions
- Project-card perspective and hover states
- A meaningful transition from the hero visual into the project showcase
- Responsive alternatives for touch devices

Specify which animations are decorative, which respond to user interaction, and which are triggered by scrolling.

Do not rely on animation alone to communicate essential content. Include reduced-motion behavior and avoid excessive camera movement or scroll hijacking.

## 8. Responsive Design

Create layouts for:
- Desktop: 1440px
- Tablet: approximately 768px
- Mobile: approximately 390px

The mobile version must be deliberately designed, not merely a compressed desktop layout. Reduce or simplify expensive 3D effects on smaller devices while preserving the identity and usability.

## 9. Use Supplied Assets

I will provide real project cover images and screenshots.

Use those exact assets as the source of truth. Do not replace them with fabricated project screenshots, random stock imagery, or AI-generated substitutes.

Create a clear mapping of the supplied assets to the portfolio sections and project detail screens.

If an asset is missing, use an explicitly identified placeholder and document what is needed.

## 10. Design System and Deliverables

Create a high-fidelity design with consistent:
- Color tokens
- Typography
- Spacing
- Grid and layout rules
- Buttons and links
- Cards and image treatments
- Responsive behavior
- Hover, focus, and active states
- Motion and interaction specifications

First explore three genuinely different visual directions for this concept. Avoid changing only the colors between them. Compare their visual identity, spatial composition, usability, and suitability for a software developer portfolio.

Then develop the strongest direction into:
1. A polished desktop homepage.
2. A responsive mobile homepage.
3. A complete selected-projects section.
4. One detailed project case-study screen.
5. The About, Skills, and Contact sections.
6. A clickable prototype demonstrating the key navigation and project-opening flows.
7. A design-system document, preferably DESIGN.md, that an implementation agent can follow.
8. A concise implementation handoff covering layout, assets, interactions, motion, and responsive behavior.

Prioritize original design, readable content, real project imagery, practical usability, and a clear path from design to implementation.

Do not start by generating a generic HTML template. The first priority is a coherent visual concept and a high-quality UI/UX design that can be handed off to Google Antigravity for production implementation.
